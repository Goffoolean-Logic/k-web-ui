An accordion is a list of sections the reader can open one at a time — FAQ, settings groups, long reference. The platform does the work: each item is a `<details>` element. There is no kit JS.

Host is `<div class="k-accordion">` of `<details class="k-accordion__item">`. The summary is `.k-accordion__trigger`. The open content is `.k-accordion__panel`. Put the same `name` on every details in the group so opening one closes the others. Omit `name` if several items can stay open. `open` on a details starts that item expanded.

The chevron is a CSS `::after` on the trigger. It flips when the item is open.

## Accessibility

Each item is a native `<details>` / `<summary>`. The platform exposes open state and keyboard (Enter / Space on the summary). Do not replace the summary with a `div`. The chevron is CSS on the trigger — it is not in the accessibility tree. Give each trigger a clear name; the panel is the following content.

## Dos and don'ts

**Do**
- Use `<details>` and `<summary>`. The platform owns open state.
- Share one `name` when only one item should be open.
- Put the answer in `.k-accordion__panel`.

**Don't**
- Build this with kit JS. There is none.
- Replace the summary with a styled `div`.
- Hide important content only in a closed accordion if the reader must see it.
