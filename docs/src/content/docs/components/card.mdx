A card groups one unit of content — a deployment, a setting, a summary — so it reads as a block on the page. It is a layout shell, not an interactive widget. Put buttons and links inside it; the card itself does not handle clicks.

Host is `<div class="k-card">`. Header, body, and footer are optional parts. The header holds a title and optional subtitle. The body is the main copy. The footer is a row for actions, aligned to the end. You can use any subset; a card with only a body is valid.

## Accessibility

A card is a grouping, not a button. Do not put `onclick` on `.k-card`. The title should be a heading (`h3.k-card__title` in the usual page outline). Actions belong in the footer as real buttons or links so they stay in the tab order and get the kit focus ring.

## Dos and don'ts

**Do**
- Use only the parts you need. A body-only card is fine.
- Put actions in the footer as real buttons or links.
- Keep one unit of content per card.

**Don't**
- Make the whole card clickable.
- Nest cards inside cards.
- Use a card as a table. That is a [table](/components/table/).
